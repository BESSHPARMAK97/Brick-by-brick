# Brick-by-brick

Цифровая платформа девелопера жилой недвижимости в Казахстане: портал проекта и дорожная карта строительства ЖК на русском и казахском языках.

**Концепция «Кирпич за кирпичом»:** данные проекта вводятся один раз, все инструменты берут их оттуда. [Концепция](docs/concept.md) · [Словарь переменных](docs/variables.md) · [Схема базы данных](docs/db/project-data.sql)

## Дорожная карта ЖК

- [Дорожная карта строительства ЖК](docs/roadmap-zhk.md): этапы, сроки, бюджет, риски, нормативная база
- **Дорожная карта в портале** (`prototype/index.html`): интерактивный инструмент
  - **Дерево этапов**: 21 этап, включая проектный комитет «Start» перед стартом продаж и СМР; этап открывается после чек-листа предыдущих. Досрочный старт с причиной, ответственные и сроки, вложения, нормативная база у каждого этапа, ачивки, мини-карта на телефоне
  - **Регионы**: сейсмоопасный юг, север с суровой зимой, запад с агрессивными грунтовыми водами, восток. Выбор региона добавляет пункты в чек-листы
  - **График**: диаграмма Ганта из связей дерева, критический путь, резервы, прогноз даты ключей
  - **Финмодель** (в «Показателях»): помесячный денежный поток, НДС 16%, кредит, КПН, IRR, NPV, чувствительность
  - **Бюджет**: план и факт по этапам, план заполняется из финмодели
  - **Сроки документов** (в «Показателях»): реестр АПЗ, ТУ, лицензий, гарантий с предупреждениями за 60 и 30 дней
  - **Проекты**: несколько ЖК в одном инструменте, у каждого свои данные; сводка по портфелю
  - **Қазақша**: переключатель языка для интерфейса и документов
- [Чек-листы перехода](docs/checklists.md) с нормами и региональными пунктами
- [Образцы документов](docs/templates/README.md): 37 шаблонов в Markdown и Word
- [Қазақша чек-парақтар](docs/kk/checklists.md) и [құжат үлгілері](docs/kk/templates/README.md)

## Портал проекта (прототип)

`prototype/index.html` — кликабельный прототип одним файлом, без сборки. Все данные в нём — пример.

- **Данные проекта** — все переменные проекта в одном месте: значение, отдел-владелец, статус (черновик, согласовано, утверждено), история изменений, базовая версия ПК Start и отклонение от неё.
- **Карточка проекта** — одна для портала и дорожной карты, общая для команды, у каждого проекта портфеля своя. Параметры подбора стандартов (регион, город, класс, этап, вид работ, конструктив), сводка из дорожной карты (текущий этап, ключи, затраты по финмодели) и реквизиты, которые подставляются в образцы документов. Этап по умолчанию берётся из дорожной карты.
- **Стандарты** — фильтры из карточки, общий чек-лист по направлениям ПР / СМР / ОГО / ОСП / БиОТ, статусы (выполнен, не выполнен, согласован, новый, изменён). В карточке стандарта: векторная схема, чек-лист выполнения, сметная номенклатура СМР и ТМЦ.
- **Дорожная карта** — этапы и чек-листы, график (весь проект или только СМР — ГПР), бюджет (план считается из финмодели, команда вносит факт), **презентация ПК Start**: 11 слайдов собираются из данных проекта (миссия и KPI, паспорт и ТЭП, ГПР СМР, рынок и цена, затраты, финансовый результат, статус данных или отклонения от базовой версии, риски и возможности, команда, предлагаемое решение), выгрузка в PowerPoint с диаграммами и в PDF. **Компания** — портфель проектов. Приложение дорожной карты работает внутри портала в изолированном блоке (shadow DOM) и берёт цвета портала.
- **Календарь событий** — ГПР, тендеры, комиссии, передача ключей, праздники РК.
- **Показатели** — сводка (качество, безопасность, сроки, финансы, поэтажная шахматка), финмодель и сроки документов.
- **Команда**, **Партнёры**.

Файл написан как страница-артефакт (без `<!doctype html>`), но открывается и локально в браузере.

## Скрипты

```sh
node scripts/check-skill-tree.js   # проверка страницы и данных (запускается в CI)
node scripts/export-skill-tree.js  # пересобрать чек-листы, шаблоны и словарь переменных из данных страницы
node scripts/build-pages.js        # собрать сайт для GitHub Pages в _site/
```

CI (`.github/workflows/check.yml`) проверяет данные и то, что выгрузки в `docs/` совпадают с данными страницы.

## GitHub Pages

Workflow `.github/workflows/pages.yml` публикует портал проекта (корень сайта, дорожная карта внутри) при каждом пуше в `main`. Чтобы он заработал, один раз включите Pages: **Settings → Pages → Source: GitHub Actions**. На Pages данные хранятся в браузере каждого пользователя; общий прогресс команды, журнал с именами и загрузка файлов работают в версии на claude.ai.
